# 国际版在线安装：两层系统检查（Test3 实验）

## 实测与定位

在线引导器资源版本为 12.1.0.25872。仅修改引导器后，用户已经进入界面，但到 60% 时再次出现系统不支持，并安装失败。

安装日志表明后续 KPacket 加载了界面 DLL；实际下载缓存包为 AMD64 KPacket **12.1.0.29681**。它仍匹配普通版自动识别家族，系统检查位于文件偏移 `0xC29C0`，与旧包的 `0xC2680` 不同。

| 文件 | SHA256 |
| --- | --- |
| 原始在线引导器 | `27d27759ad6d159a908ac7ec6ce3eba5623acafa117a64644138673a6cbd2a31` |
| 本次实际下载的 29681 缓存包 | `4382abdb04958721fc8c56e005feb02470f9146d351749005f9836baee1120aa` |

在线引导器会检查缓存安装包的证书，并以 `-installCallByOnlineSetupAndShow` 等参数启动下载的安装程序。只修补引导器不足以通过第二层；直接修改缓存文件也可能触发缓存校验失败。

## Test3：限制分析范围，在启动事件中修改内存

`Patch/Online/Start-Online.ps1` 使用 Windows 原生调试进程接口启动原始引导器。在进程创建事件暂停期间：

1. 针对精确原始引导器，在实际加载基址加 RVA `0x67500` 的位置修改系统支持函数六字节。
2. 对后续较大的 WPS/Office/KPacket 安装进程，按现有 AMD64 指令家族和全部结构守卫识别共享系统检查。
3. 核对目标内存原始字节，临时调整该区域保护、写入六字节、恢复保护并验证，然后继续官方进程。

此实验不修改两层磁盘 EXE，不修改实际系统版本查询、下载 URL、文件证书或缓存验证逻辑。它使用调试接口自动处理创建事件，不要求用户操作 x64dbg。

实验范围：64 位 Windows PowerShell，原始在线引导器为上述精确哈希；后续 AMD64 安装包按家族动态识别。需要能调试引导器和其安装子进程的权限，测试时以管理员身份运行脚本。关闭脚本或超时将尝试分离，设置了关闭调试器时不杀死进程。

## 使用

把原始 5.4 MiB 在线安装器放在 `Patch/Online/Original` 下，保留原文件名 `wps_wid.cid-424762483.1792948203(1).exe`，然后以管理员身份运行 `Start_Online_Test3.cmd`。也可把原始 EXE 拖到 CMD 上。

测试发布包包含用户提供的原始引导器，仓库不包含厂商 EXE。仓库使用共享的 `Patch/WPSStandard.Core.ps1`；便携测试包将该文件放在启动脚本旁边。

请保持脚本窗口打开，按官方界面继续下载与安装。失败时提供 `Online_Test3_Result.txt` 和最新 `wpssetup.log`。

**当前状态：Test1 启动已通过、后续安装失败；Test2 在子进程分析期间出现“数组维度超出了支持的范围”，第二层补丁未应用；Test3 尚待用户验证完整安装。**

Test3 不再读取整个约 361 MiB 的自解压包。C# 根据 PE 节表只读取参与代码与结构验证的文件前部（29681 为 7,517,696 字节，约 7.17 MiB），排除安装数据 overlay；所有原有代码、调用、重定位和接口检查仍保留。增加读取、验证耗时及失败调用栈日志。 原生接口自动测试覆盖 WOW64 父进程/AMD64 子进程创建事件、内存读写与恢复、继续执行及正常退出。这些测试不代表 WPS 在线安装已经成功。
