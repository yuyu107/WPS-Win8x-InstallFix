# 专业版 29161：官方安装器成功方案

## 结果

2026-11-10，用户确认 WPS 专业版 12.1.0.29161 修补后在 Windows 8.1 **成功完成安装**。最终保留原官方 EXE、安装界面、文件释放和组件注册流程，仅修改外层系统支持检查的 3 字节。未重构安装器、未手动部署 WPS 文件、未使用扩展内核。

普通版/国际版为 NSIS 外壳与 x64 内层路线；此专业版的外层是 PE32 KPacket。不能套用普通版的提取偏移或 x64 函数入口补丁。

## 调用关系

以下 VA 基于 EXE 首选 ImageBase `0x400000`；DLL 用相对位置表示。

| 位置 | 事实 |
| --- | --- |
| DLL `+5C1B` | 调用接口虚表 `+D4`；结果用于决定继续或显示系统限制提示 |
| EXE `0x5480C0` | 构造传给 DLL `xmain` 的接口，虚表为 `0x85EEB8` |
| EXE `0x54EDB0` | 虚表 `+D4` 实现，跳转到 `0x4A6BF0` |
| EXE `0x50F836`、`0x50FEFF` | 后端安装流程直接调用同一 `0x4A6BF0`，返回零进入另一分支 |
| DLL `+253C0`、`+25150` | 根据日志是 `setKPacketInstallPath` 和 `setKPacketCheckBoxes`，主要写入安装设置 |
| DLL `+2804D` | 调用接口 `+34`，经 EXE `0x54FA60` 进入 `0x50F490` |

因此只改 DLL 中提示之后的 EAX，无法改变后端再次调用系统支持函数的结果。此前界面出现却卡 3% 的现象，与这条静态调用关系一致；完整动态栈未留存，不能声称已逐条还原当时的阻塞。

函数通过 `support/InstallOnServer2008` 配置、系统版本及工作站/服务器类型决定支持状态。应修改这个共享系统检查，保留 DLL 的其它界面和安装逻辑。

## 最终 3 字节

| 项目 | 值 |
| --- | --- |
| 函数 VA / RVA | `0x4A6BF0` / `0xA6BF0` |
| 文件偏移 | `0xA5FF0` |
| 原字节 | `6A 00 68` |
| 修改字节 | `56 EB 6A` |
| 原成功返回 VA | `0x4A6C5D` |

```asm
; 原函数入口
push esi
jmp  success  ; 短跳，从函数入口 +3 跳到 +0x6D

; 原函数已有代码，保持原字节
success:
mov eax,1
pop esi
ret
```

保存与恢复 ESI 成对，调用者栈和返回地址保持正确，返回值为完整的 EAX=1。

## 早期 Test1 错误及修正

早期曾用 `B8 01 00 00 00 C3` 覆盖函数开头 6 字节，但这里有 HIGHLOW 重定位项 `RVA 0xA6BF3`。原先它修正 `push` 的绝对地址操作数；覆盖后 Windows 仍应用该项，会修改新代码。

例如加载到 `0x120000` 时，基址差值为 `-0x2E0000`，上述 `ret`（C3）变为 95。磁盘 SHA256 正确不能保证内存指令正确。该缺陷已在最终方案中修正：只改重定位项之前的 3 字节，保留 `+3` 和 `+8` 的原操作数，并跳过这些原指令。

Test1 的“后台驻留无窗口”报告同时记录过另一个进程成功加载 kpacketui.dll。报告没有异常转储，不应把某个进程的最终故障地址或退出方式写成已证实事实。
