# WPS Office Windows 8.x 安装限制：技术分析

## 背景与观察

在 Windows 8.x 上测试 WPS Office x64 离线安装器时，原版安装器提示“仅支持 Windows 7、Windows 10、Windows 11”。用户测试表明普通 Windows 7 兼容模式未能通过检测，但修补两个已知构建的共享版本检查函数后，都可以进入图形安装界面。

这不是对软件全部功能的兼容性认证，尚未验证完整安装及运行。

## 两个版本与安装结构

- 12.1.0.29158，中国大陆离线版，外层 32 位 NSIS，内嵌原生 x64 安装器。
- 12.1.0.29162，国际版离线安装器，采用相同的封装思路。

在线安装器与离线安装器不是同一个可执行文件。官网在线安装的行为不能直接外推到相应离线 EXE。

## 已识别的内层代码

两个内层 x64 EXE 的共享版本检测函数虚拟地址均为 `0x1400C3280`，对应文件偏移 `0xC2680`。

原始入口 6 字节：

```asm
40 53 48 83 EC 20
```

修改为：

```asm
B8 01 00 00 00 C3    ; mov eax, 1; ret
```

这会让该函数立即返回 1，而不是执行原来的检测逻辑。仅针对这两个 **SHA-256 精确匹配**的构建实施。不能将同一偏移无条件应用于其他 WPS 版本。

此前 v0.1 曾针对两个调用点进行修补，未解除安装界面拦截。v0.2 改为修补共享版本检查入口，29158 用户测试可打开安装界面；v0.3 以同一原理处理 29162，用户也反馈能够打开安装界面。

## 为什么 Windows 7 兼容模式无效？

Windows 应用兼容层不等于完整虚拟化一个 Windows 7 操作系统。程序可以通过不同 API、文件版本资源、模块内逻辑或子进程判断运行环境。静态分析可看到版本检测相关的接口与字符串，但**不能仅凭引用断言某条具体路径一定被执行**。

因此，目前能够确认的是“兼容模式启动仍被拦截，共享函数修补后可进入安装界面”，而非已动态证实兼容层被哪一个具体 API 绕过。

若需要精确追踪，应在受控测试虚拟机内比较 `VerifyVersionInfoW`、版本资源 API 及相关进程的实际调用、返回值与分支。

## 补丁安全性与限制

- 只修改原始内层安装器的**副本**，原始文件保留；不替换系统 DLL、不修改内核。
- 原厂 Authenticode 签名在修改后失效。
- 使用外层 SHA-256、提取后内层 SHA-256、入口字节和输出 SHA-256 四重校验。
- 修补并不能解决 WPS 主程序可能存在的缺失 API、安装后升级或其他独立兼容性问题。
- 研究文档不构成 WPS 官方支持声明。
